# OOXML Explorer Services & RAG Architecture

This directory contains the core business logic, database, and AI service engines for the OOXML Explorer application.

---

## RAG Data Flow & Ingestion Pipeline

To provide accurate explanations of XML elements with official ECMA-376 citations and Microsoft Open XML SDK mappings, the application uses a hybrid Retrieval-Augmented Generation (RAG) architecture.

```
                         [ Ingestion Phase ]
 REFERENCE_TAGS -> [mastra/index.ts Workflow]
                         |          |
                         | (Step 1) | (Step 2)
                         v          v
   public/generated-rag.json      services/staticKnowledgeBase.ts
               |
    (Verification & Calibration)
               v
      public/rag-data.json
               |
               v
       [ Runtime Phase ]
    • Fast offline static fallback
    • Loaded into IndexedDB
```

### 1. The Datasets
*   `public/rag-data.json`: The **Golden Reference Dataset**. It contains verified, structured OOXML schema information (definitions, attributes, parents, official ECMA-376 citations, and Open XML SDK class mappings). This is the source of truth for the RAG engine.
*   `services/staticKnowledgeBase.ts`: The **Static Offline Fallback Knowledge Base**. This is an auto-generated TypeScript file compiled from the golden dataset. It contains the most common/critical tags and is bundled directly with the application to provide immediate offline access before IndexedDB is initialized.
*   `public/generated-rag.json`: The raw output dataset generated by running the Mastra pipeline.

### 2. The Mastra Ingestion & Compilation Pipeline
*   **[src/mastra/index.ts](file:///Users/adbindal/code/exp/ooxml-explorer/src/mastra/index.ts)**: Defines the Mastra workflow (`ooxml-rag-ingestion`) and its steps:
    1.  `generateSchemaStep`: Calls the LLM via `jetski --print` to generate structured JSON metadata for all tags.
    2.  `compileKBStep`: Compiles the generated tags into `services/staticKnowledgeBase.ts` and saves them to `public/generated-rag.json`.
*   **[scripts/ingest_rag.ts](file:///Users/adbindal/code/exp/ooxml-explorer/scripts/ingest_rag.ts)**: Runs the Mastra workflow with a list of core OOXML tags to trigger the full generation and compilation process.
*   **[scripts/diff_rag.ts](file:///Users/adbindal/code/exp/ooxml-explorer/scripts/diff_rag.ts)**: Compares the generated dataset against the golden dataset, reporting any mismatches so developers can calibrate the LLM prompts.

### 3. Running Ingestion
To run the ingestion and compilation pipeline:
```bash
npx tsx scripts/ingest_rag.ts
```

### 4. Runtime Execution
*   **[services/storageService.ts](file:///Users/adbindal/code/exp/ooxml-explorer/services/storageService.ts)**: On application start, initializes IndexedDB (`ooxml_explorer_db`) and populates the `rag_schemas` store by fetching `/rag-data.json`.
*   **[services/ragRouter.ts](file:///Users/adbindal/code/exp/ooxml-explorer/services/ragRouter.ts)**: Intercepts queries for XML elements, retrieves their schema/citations from IndexedDB (falling back to `staticKnowledgeBase.ts` if not found), and injects it as grounding context into the Gemini API request.
